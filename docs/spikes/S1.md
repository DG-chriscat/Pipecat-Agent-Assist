# Spike S1: bot joins a Daily room and talks

Date: 2026-11-15. Card t_a4e29252. Pipecat 1.15.0, daily-python 0.38.0.

## Result

WORKS. The bot creates (or takes) a Daily room, joins as "Intake Bot", greets the
first participant in well under the 2 s budget, transcribes the caller, and replies
through the LLM.

## Setup

- Pipeline: `DailyTransport` in -> Deepgram STT `nova-3-general` -> user aggregator
  (Silero VAD + Pipecat's default Smart Turn v3 stop strategy) -> LLM -> Deepgram TTS
  `aura-2-thalia-en` (websocket) -> `DailyTransport` out -> assistant aggregator.
- LLM: Anthropic `claude-haiku-5-5`, max_tokens 300, built by
  `agent_assist_bot.llm.create_llm()` (the one swap point; `LLM_PROVIDER` / `LLM_MODEL`
  env overrides).
- Greeting is a fixed `TTSSpeakFrame` queued on `on_first_participant_joined`, so it
  does not wait on the LLM.
- Rooms: created through the Daily REST API with `exp` = now + 540 s and
  `eject_at_room_exp`, deleted when the bot / test exits (`DailyRoomsClient.temporary_room`).
- Test harness (`bot/tests/harness/`): a daily-python `CallClient` joins as "caller",
  publishes a custom audio track fed with Deepgram TTS audio generated at test time
  (voice `aura-2-arcas-en`), and records every remote participant's microphone audio
  with wall-clock timestamps. Speech onset is found by RMS energy on 20 ms chunks.
  What the caller heard is transcribed with Deepgram prerecorded `nova-3` to check content.

## How it was measured

- Greeting latency: harness join-completion time -> first 20 ms chunk of bot audio
  above RMS 300 received by the harness. This is end to end, including the bot seeing
  the join event, TTS first byte, and Daily network transport.
- Reply latency: end of the caller's audio playback -> first bot audio above threshold
  received by the harness (user perceived response time).
- Bot side breakdown from Pipecat metrics logs (runs 2 and 3; run 1 logs were not kept).

Command: `uv run pytest -m live bot/tests/test_live_s1.py -s` (3 runs, all passed).

## Observations

- Greeting: comfortably inside 2 s (0.18 to 0.50 s). TTS first byte is ~0.1 s; the rest
  is the join event reaching the bot and Daily transport.
- Reply: ~2.3 to 2.4 s typical, one 4.6 s outlier (run 1, no bot log kept so the stage is
  unknown). The largest pieces are LLM TTFB (~1.0 s) and end of turn detection (0.6 to
  0.9 s). Levers if this matters for intake: a faster/streaming-optimized model behind
  `create_llm`, tuning the user turn stop strategy, or a shorter system prompt.
- The first word of the greeting ("Hi,") is consistently missing from what the harness
  records, though the bot sends it. Most likely the harness's audio renderer for the bot
  is attached a moment after the bot starts sending. Treat greeting latency as "first
  audio the caller hears". Worth checking with a browser client in S4.
- Deprecation warning from Pipecat 1.15.0 itself (`AudioContextTTSService`), not from our code.

## Open items

- Phone audio (8 kHz, dial-in) is S3; these numbers are for WebRTC.
- `on_participant_left` cancels the bot; for multi-party calls (S2 and later) the end
  condition needs to change.

# Spike S4: browser joins the call room with a meeting token

Status: partially verified. The token endpoint works against the real Daily API. Joining any
room on `dg-chriscat` currently fails with an account error (see Result below).

## What was built

- `POST /rooms/{room_name}/agent-token`, body `{"user_name": "..."}`. It calls the Daily REST API
  `POST /v1/meeting-tokens` with `room_name`, `user_name`, `is_owner: false`, and
  `exp = now + 3600`. The response is `{"room_name", "token", "expires_at"}`.
  - `DAILY_API_KEY` missing: 503
  - Daily returns an error or can't be reached: 502 (Daily's response body is not passed through)
  - `user_name` empty or missing: 422
- `GET /spike/agent` serves a static page (`server/agent_assist_server/static/spike_agent.html`).
  It loads `@daily-co/daily-js` from the unpkg CDN, gets a token from the endpoint above, joins
  the room with audio only, lists participants with their mic state, plays remote audio, and has
  Mute/Unmute and Leave buttons.
- Unit tests (`server/tests/test_agent_token.py`) mock Daily HTTP. They cover success, a Daily
  error, Daily being unreachable, a missing key, a missing or empty `user_name`, and serving the
  page.
- Live test (`server/tests/test_agent_token_live.py`, `@pytest.mark.live`). It creates a private
  room, fetches a token from the endpoint, checks the token with Daily
  (`GET /v1/meeting-tokens/{token}`), joins with `daily-python` using only that token, checks that
  the local participant `userName` and the room presence both show the requested `user_name`, then
  deletes the room.

## Run the server and open the page manually

```bash
uv sync --all-packages
export DAILY_API_KEY=...            # never commit; see .env.example
uv run uvicorn agent_assist_server.app:app --reload --port 8000
```

1. Create a room (or use one the bot created in S1/S3):
   ```bash
   curl -s -X POST https://api.daily.co/v1/rooms \
     -H "Authorization: Bearer $DAILY_API_KEY" -H "Content-Type: application/json" \
     -d '{"privacy":"private","properties":{"exp":'$(( $(date +%s) + 3600 ))'}}'
   ```
   Copy the `url` from the response, for example `https://dg-chriscat.daily.co/<name>`.
2. Open http://localhost:8000/spike/agent in Chrome. Paste the room URL, enter an agent name,
   and click Join. Allow microphone access. The browser needs `localhost` or HTTPS for
   getUserMedia.
3. Your name shows in the participant list. Join the same room from a second tab or device
   (with another token, or by opening the room URL directly if the room is public) and check
   that both participants appear and that Mute changes the mic state shown on the other side.
4. To fetch a token without the page:
   ```bash
   curl -s -X POST localhost:8000/rooms/<name>/agent-token \
     -H "Content-Type: application/json" -d '{"user_name":"Agent Alice"}'
   ```
5. Delete the room afterwards: `curl -X DELETE -H "Authorization: Bearer $DAILY_API_KEY"
   https://api.daily.co/v1/rooms/<name>`.

Run the live test:

```bash
uv run pytest -m live server/tests/test_agent_token_live.py -s -v
```

## Result (2026-11-15)

- Endpoint to Daily token: works. Daily confirms the token has the right `room_name`, the
  requested `user_name`, is not an owner, and expires in 1 hour.
- Room create and delete through the REST API: works.
- Joining as a client: fails before any media is set up, with
  `Connection(Api(RoomLookup(RoomInfoError(Unhandled("account-missing-payment-method")))))`.
  A public room joined with no token fails with the same error, so the cause is the Daily
  account, not the token. The browser page will fail the same way until the account is fixed.

Open: add a payment method to the `dg-chriscat` Daily account (or confirm another domain or key
to use), then rerun the live test and the manual browser check. S1 (the bot joins a room) will
hit the same error.
